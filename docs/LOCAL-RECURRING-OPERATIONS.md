## Schedule, health and digest

Three roles run: scheduler, browser and offer. The offer role also prepares media and handles maintenance jobs. The scheduler checks every thirty seconds for Hanoi starts at 06:00, 10:00, 14:00, 18:00 and 22:00. A ninety-second tolerance accommodates polling; older missed windows never create catch-up collection bursts. Each slot is idempotent and closes within twenty minutes of its scheduled start, including planning. An overlapping manual run makes the slot missed. Restarts cancel queued work whose window expired.

Frontier allocation remains 40% refresh / 40% search-profile / 20% FYP with spillover. Unresolved offer evidence requests the next eligible slot; ordinary posts refresh daily and established profiles weekly. Source access is distinct from inventory. Existing admin pause/cancel controls remain available. Admin-only `/v1/admin/operations/status` reports role heartbeats and active-lease health, recent slot outcomes, actual non-demo coverage, spending and proof readiness. A valid renewable lease counts as worker activity during long jobs. Content-free operational alerts are projected into the admin health API and delivered through a durable job outbox to owned local JSONL logs. Only state/details changes create delivery versions; acknowledgments are version-fenced, and resolved incidents and log files expire after thirty days. File delivery is at least once; consumers deduplicate event_id. No email, social message or webhook is sent.

After the final slot closes, a Hanoi-day digest freezes durable changes. Offline days become explicitly partial at startup after scheduling was activated. An installation never enabled does not generate fake digest days. Late enrichment waits for the next digest. ## Retention and deletion

Expiry removes derived claims, analysis/review copies, canonical evidence, recognition results, source-linked digest entries and catalog eligibility. Content-free identity tombstones support deletion/deduplication. Media/vector and checkpoint cleanup use durable jobs; checkpoint removal covers snapshots, blobs and intermediate writes.

A model response arriving after deletion settles its financial receipt without restoring its result. Media dependency receipts cover image-only evaluation calls without an offer. Checkpoint writes hold a shared application execution lock, preventing a withdrawn execution from recreating state after purge. Cancellation can retain a financial receipt; uncertain reservations are never automatically replayed or refunded.

## Daily native backup and local alerts

`BACKUPS_ENABLED=false` is the default. After the separately commanded activation, the scheduler queues at most one current Hanoi-day backup after 06:00 while awake, cancels old queued backup work and avoids a catch-up burst. The offer worker runs native `pg_dump` against the configured PostgreSQL database, streams separate retained media and deletion artifacts, and publishes SHA-256/size manifests only after successful exports. Install a matching PostgreSQL client. `python -m bouquetbrowse.cli backup-native` is an explicit manual backup command. CLI arguments contain no database password; the child receives a minimal client environment.

Snapshots live in owned `BACKUP_DIRECTORY` (default ignored `.data/backups`) and expire after seven days. Retention checks markers, member names and hashes, refuses symlinks/unowned extra files, and deletes only individually verified files. A separate current-deletions ledger updates when durable deletion records change; keep that ledger with restore materials. Incomplete exports never count as successful backups. A restore is an operator action, never an automatic recovery burst.

Alerts cover stopped configured workers, failed/stale work, uncertain paid calls, near-limit monthly spending, stale discovery and overdue enabled backups. Their API and owned local files contain curated codes, counts and IDs; captions, credentials and buyer content are excluded. A valid active job lease counts as worker activity. Disabled backups/recurring collection do not pretend to be active or trigger missing-worker/backup alarms.

`deploy/manage-local-tasks.ps1 -Action status|disable|uninstall` operates only on the three exact tasks carrying the BouquetBrowse ownership description. Disable stops running owned tasks and disables future starts; uninstall additionally unregisters them. Startup installation and real collection remain deferred until your command.
